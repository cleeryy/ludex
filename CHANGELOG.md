# Changelog

All notable changes to Ludex are documented here. The format is based on
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project follows
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- The install/download queue can be reordered (#202): a persisted
  `queue_position` and a real scheduler start the lowest-position queued job
  when a slot frees, so a newly added game can jump ahead of older jobs; the
  Downloads screen shows the queue rank with move-to-top/up/down controls
  (running and finished jobs are refused), the queue compacts after completion,
  and classic and stream installs share the same order.

## [0.4.3] - 2026-11-12

### Added

- Account settings sync through the server (#201): a validated per-account
  preference document (`user_preferences`, revision/If-Match, 64 KiB cap,
  allowlisted keys) carries theme, language, Big Picture layout, sound/haptics,
  library view and update reminders across devices; the web hydrates before the
  first render, debounces writes, queues offline changes, resolves conflicts
  explicitly, and the desktop mirrors account-owned fields into `settings.json`
  without touching device paths. Secrets and paths never sync.
- Big Picture has its own sound and haptics language (#198): 14 original cues
  generated by a committed synthesis script (mono 48 kHz, dry, no samples or
  console motifs) for move, confirm, back, launch, error, install complete,
  power and more, with dedupe, silence while a game runs, reduced-motion
  handling and a volume setting; pad haptics gained per-cue patterns and an
  Off/Standard/Strong strength setting, and keyboard/mouse never rumble.
- Two new Big Picture layouts (#197): a Switch-style bottom Dock and a
  PlayStation-style Spotlight, selectable in Settings → Appearance and in the
  console settings; each has its own keyboard/gamepad navigation (zones, wrap,
  focus restoration on switch), the existing layouts stay available, and the
  choice persists and applies immediately.
- Ludex artwork for the Sunshine console app (#207): the managed `Ludex` app now
  publishes a bundled 600x900 box-art `image-path`, materialized once under the
  app data directory with a content hash (refreshed on change, old copies
  pruned), so Moonlight shows the logo instead of a blank tile.

### Changed

- Network architecture decision record (#200): `docs/NETWORK-ARCHITECTURE.md`
  evaluates direct vs Caddy, port-forward/UPnP, parallel ranges, TCP/BBR tuning,
  STUN/TURN and QUIC/HTTP3 against the measured path (and notes the desktop
  client is HTTP/1.1 today), with explicit decision thresholds;
  `scripts/bench-download.sh` runs the whole measurement matrix and prints
  verdicts, and the deploy/performance docs cover Caddy, HTTP/3 and the numbers
  to collect. No speculative protocol code.

### Fixed

- Stream installs resume instead of restarting (#203, #204, #205, #208):
  retries reuse the same job id and history row, the desktop persists the job
  request and rebuilds a worker for paused/failed/interrupted jobs (including
  from a previous app run) at the exact `.part`/entry checkpoint, the per-entry
  stream gained a stall timeout with bounded backoff and exact-byte Range
  resume, non-resumable formats fall back to the classic resumable download
  before writing anything, and the UI distinguishes Resume from Restart with an
  explicit confirmation.
- The remote-play wizard shows the VPN/mesh address (#206): it enumerates every
  interface, prefers Netbird/Tailscale/WireGuard/ZeroTier addresses over the
  default-route LAN IP, never advertises CGNAT, Docker, loopback or link-local
  addresses, lists alternatives to copy, and warns when a VPN is detected
  without an address.

## [0.4.2] - 2026-11-12

### Added

- One shared one-shot elevation flow (#192): privileged actions go through a
  whitelisted elevation module (path ACL, signed installer, service/driver,
  firewall rule, config write) that validates every path, launches a single
  hidden helper with one UAC prompt and maps cancellation, timeout and failure;
  the Sunshine grant now uses it, the runtime installer and remote-play wizard
  reuse it, and a reusable confirmation dialog shows the exact operation,
  target and reason before asking.
- Resume and Force close on the game page (#191): while a game runs, Overview
  shows Resume as the primary action (finds the game's top-level window by PID,
  restores and focuses it, or tells you to alt-tab when no window can be found)
  next to a confirmed Force close that stops the whole process tree; the running
  session is polled and cleared on `game://exited`.
- Big Picture is a complete console shell (#196): a top system bar (time,
  account/avatar, server and online state, downloads, pad family, battery), a
  home row (Continue, Library, Downloads, Collections, Settings, Power), an
  in-shell Settings app (language/account, appearance, controllers, streaming)
  and a mode-aware power screen with confirmations. Keyboard/gamepad navigation
  works on every surface, apps are URL-addressable, and the layout scales with
  safe areas down to 720p.
- Account and server default language (#188): users carry a `locale` preference
  (exposed on `/api/me`, login/OIDC responses and the account profile), admins
  set a server default published in the public config, and the web resolves
  device override → account → server → system → English with no flash on reload.
  The language panel shows the effective value and its source, lists every
  registered locale (below-gate ones visible but disabled with the reason),
  saves to the account by default with a device-only option, and the desktop
  mirrors the account locale for game-config sync.

### Changed

- Network speeds are shown in bits per second (#199): download, update, stream
  and bandwidth-cap figures now read `Kb/s`/`Mb/s`/`Gb/s` (decimal), while file
  sizes stay in bytes; the cap is edited in Mb/s and still stored as KiB.
- The game page now reads like Settings (#189): one sticky sub-nav and one group
  at a time (Overview, Files, Launch, Settings, Saves, Achievements, ROM),
  addressable with `?tab=`, one 1240px content width, consistent headings and
  empty states, editor-only actions moved into their group, duplicate hero/aside
  facts removed, and every panel region named for screen readers. No visual
  redesign.

### Fixed

- Large downloads survive dropped connections (#195): an idle timeout detects a
  stalled stream, the client reconnects with bounded backoff and `Range` from the
  last flushed byte, shows "Connection lost, resuming from X%", and restarts
  explicitly when the archive changed; the server logs per-stream
  bytes/elapsed/outcome and rate-limits reconnect storms. The download path also
  got larger stream chunks, a stable ETag, TCP keepalive/NODELAY, a documented
  measurement matrix and `scripts/bench-download.sh` (#194); parallel ranged
  downloads wait for measurements on the user's network.
- The in-game overlay now says why it does not open and self-heals (#190):
  `overlay_status` reports controller names/ids, trigger deliverability (the
  Guide button is never delivered on Windows XInput, so the chord fallback is
  used), global and per-game enablement, presentation/fullscreen state, the
  running game pid and the last trigger verdict; the listener restarts with
  capped backoff, re-arms on hot-plug, logs every trigger and open/close attempt
  with its reason, creates and focuses the overlay window on demand, and
  Settings → Profiles shows the checklist plus an "Open the overlay now" test.
- PowerShell/console windows are gone for good (#193): every internal helper,
  silent installer and runtime setup now goes through the no-window helper, the
  source-scan test covers twelve programs plus `.exe`/absolute-path literals,
  the game installer's interactive-vs-silent window choice is explicit instead
  of inferred from the timeout, and game/emulator/Moonlight spawns stay
  user-visible by marker.
- Windows updates now replace the app binary (#186): every build carries a
  `LUDEX_BUILD_COMMIT` stamp, the updater records the version it installs and
  verifies it on the next start, startup logs the running exe/version/commit and
  warns about a second `ludex.exe` in the usual install roots, and a mismatch
  shows a danger toast instead of "updated". The NSIS bundle is pinned to a
  per-user install and the release CI verifies the payload's build stamp.
- Adopted games on Windows launch again (#187): verbatim `\\?\` paths are
  normalized before `Command::new`/`current_dir` (drive and UNC forms, keeping
  the prefix only past MAX_PATH) at launch, adoption storage and DB reads, the
  working-directory override is persisted and wins over the adopted rule, and a
  process that dies within 5 s now surfaces a danger toast with its exit code
  (`0x…`) instead of doing nothing.

## [0.4.1] - 2026-11-12

### Added

- Guided "Make it run" runtime installer (#178): diagnoses why a game cannot
  launch, shows a numbered consent-gated plan, downloads and extracts from an
  allow-listed catalog (UMU/GE-Proton on Linux, VC++/.NET/DirectX on Windows,
  Rosetta/wrappers/GPTK import on macOS) with size/checksum limits, progress
  events and cancel, and records installs plus per-game choices locally so a
  runtime can be reused or removed.
- Server-side device registry and targeted remote installs (#184): each desktop
  registers a stable device id and heartbeats every 25 s (platform, app version,
  installed game count, free disk, streaming availability); the phone lists
  "Your PCs" with online/offline state and can target an install at one device.
  Offline targets stay queued until the PC reconnects, revoked devices are
  rejected, and the account-wide queue still works when no device is chosen.
- User avatars (#183): accounts can upload a PNG/JPEG/WebP logo (magic-byte
  checked, 2 MiB and 4096x4096 capped) and remove it; files are stored
  content-addressed with old-file cleanup, and the avatar shows in the sidebar,
  account menu, community profile, activity feed and member lists with an
  initials fallback. Private profiles keep initials on public surfaces.
- Remote play away from home (#179): a VPN-first wizard detects the LAN IP,
  VPNs, Sunshine config/ports and the router's UPnP IGD, then offers an advanced
  consent-gated mapping mode with a short lease, per-port verification, a
  mapping-removal action and automatic cleanup (startup sweep included). CGNAT,
  double NAT, public/non-private IGDs, unsafe Sunshine origins and ports owned
  by other programs are refused; the Sunshine Web UI port and mDNS are never
  mapped. Moonlight instructions and a cleanup summary close the flow.

### Changed

- Save folders confirm themselves (#180): high-confidence paths (manifest match,
  Steam ground truth, already confirmed) are promoted without a prompt, the
  pre-launch snapshot is diffed against the post-exit tree so changed candidates
  are promoted automatically (one → that path, several → all with the largest as
  primary, none → keep the confirmed path), and broad roots, symlinks, oversized
  folders and folders that did not exist before are skipped with a visible
  reason; the panel shows "Saving", "Waiting for the first session" or
  "Skipped: too broad" instead of asking for a confirmation.
- Game archive uploads keep running when you leave the Upload screen (#185): an
  app-wide upload provider owns the resumable chunk loop and server session, the
  screen is only a view of it, a shell indicator shows live progress from any
  route, completion refreshes games/stats/scan with a toast, cancel deletes the
  server session, and a reload offers to resume from the received parts.

### Fixed

- The game page no longer freezes on open (#159): `list_game_configs`,
  `game_config_adapters` and `stream_target` now run on the blocking pool
  instead of the UI thread, and a scan slower than 50 ms logs one warning with
  its directory/file counters so lag can be measured in the field. The
  engine-adapter walk also skips bulk asset folders (`Content`, `Data`,
  `Engine`, `Binaries`, `Paks`, `Movies`, `Audio`) and non-config files; the
  raw config editor keeps listing every supported config, including those under
  asset folders (#147).
- The cloud-save panel no longer blocks the game page (#159): the status scan
  runs on the blocking pool with hard caps (50,000 entries, depth 64, deadline),
  a 45-second cache invalidated by detection or exit changes, and the section
  mounts lazily with a skeleton; a slow or failed server call cannot freeze the
  page, and media thumbnails load lazily.
- Windows desktop updates now show the new web UI immediately: Tauri no longer
  registers the PWA service worker, and the WebView2 `Service Worker`/`Cache`
  directories are reset once per app version before the window opens (#177).
- Sunshine publishing from a Program Files install now offers an explicit
  one-time UAC grant for the config folder instead of requiring Ludex to run as
  administrator; cancelling changes nothing and later syncs work without a
  prompt (#182).
- Internal Windows helper commands (`reg`, `powershell`, `cmd`, Ludusavi,
  winetricks, `secret-tool`, `xdotool`) no longer flash console windows: every
  helper spawn goes through one `process::command`/`capture` helper that sets
  `CREATE_NO_WINDOW`, while game, emulator and Moonlight launches keep their own
  window (#181).

## [0.3.1] - 2026-11-11

### Added

- Desktop SSO through the web page (#157): the desktop app opens
  `{server}/#/login?desktop_state=…` in the system browser; after SSO or
  password login the authenticated web page creates a state-bound one-time
  handoff (120 s TTL, single use, in-memory, rate-limited) and the desktop polls
  and redeems it through the existing `/api/auth/oidc/exchange` — no loopback
  listener, no custom scheme, no JWT in any URL. The SSO button now appears in
  the desktop app with progress/cancel/error and an "Open web login" fallback.
  Audit records create/claim/failure without state or code; limits and TTL are
  configurable (`LUDEX_DESKTOP_HANDOFF_TTL_SECONDS`).
- Auto-managed Ludusavi manifest (#153): the desktop app downloads the
  canonical manifest into `{appDataDir}/manifest/` with ETag/304, atomic
  replace, optional checksum verification, size/timeout limits and a 24 h
  throttle; the previous copy is kept on any failure and an explicit consent
  toggle controls automatic updates (URL override supported). Detection
  precedence is explicit path → managed copy → user manifest → optional CLI,
  and Settings → Save database shows version, timestamps, size, source and
  Update/Remove actions with the MIT/CC BY-NC-SA attribution. No manifest is
  bundled in the repo or image.
- Drive-based install root suggestions (#145): `suggest_storage_locations`
  detects writable fixed drives (Windows) or common mounts/home (Linux/macOS),
  proposes `<drive>:\Games` / `~/Games` with free space, writability and a
  recommended default (current choice, else largest free, else app-data), and
  never creates a directory. Settings → Storage gains a quick-add panel with
  checkboxes, roles and nearly-full warnings; the install dialog preselects the
  recommendation for users who never confirmed a root, while existing paths are
  untouched.
- Generic text config editor (#147): every INI/CFG/CONF/TOML/JSON/INFO file
  under the install folder is listed and editable — the crack/Steam-emulator
  name blacklist is gone (only hidden dirs, Wine `drive_c`, symlinks and files
  over 1 MiB are skipped, the latter listed read-only with a reason).
  UTF-8 ±BOM, UTF-16LE/BE and Windows-1252 round-trip with their exact
  encoding/BOM and CRLF/LF; unrepresentable values are refused, restore writes
  the backup bytes verbatim, and the UI never queries a read-only file.
- Sunshine/Moonlight Windows fixes (#150, #151): empty/whitespace/BOM/UTF-16
  `apps.json` is treated as "no apps yet", re-encoded in its original format on
  write with byte-exact backups, and `Program Files` permission failures are
  reported explicitly (no silent copy); Tauri string rejections now surface in
  toasts instead of "Something went wrong". Moonlight on Windows is detected
  through the portable `Moonlight.ini` and the read-only
  `HKCU\SOFTWARE\Moonlight Game Streaming Project` registry (injectable
  reader), with distinct not-found/unreadable/no-host messages and a manual
  host fallback.
- Theme system beyond light/dark (#140): five complete data-driven themes
  (midnight, light/Paper, nord, gruvbox, amber) with 26 semantic tokens each,
  a system-following option, custom accent and background tint with measured
  WCAG AA contrast (focus rings 3:1, TV 7:1/4.5:1), JSON theme import/export
  with validation, no-flash startup from `localStorage`, and a live Settings →
  Appearance preview. Big Picture uses the same tokens with a TV variant;
  hardcoded colours are gone from components and a test enforces it. Legacy
  dark/light/system preferences migrate automatically.
- Installable desktop prereleases on every `main` push (#149): a new
  `edge-desktop` CI matrix (Linux AppImage/deb, Windows NSIS) stamps a
  monotonic `<next patch>-edge.<run_number>` version for the build only, signs
  the bundles, merges the updater `latest.json` and uploads them with
  `.sha256` checksums to the rolling `edge` prerelease; the same files are kept
  as a 14-day workflow artifact. E2E-gated, never on pull requests; stable
  releases and `/releases/latest` are untouched.
- Executable pickers in Launch options (#143): `list_game_executables` walks
  the installed folder (depth 4–8, loop-safe, root-confined, 5 s cache) and
  classifies entries as launch/installer/uninstaller/other with the detected
  main executable marked "Detected". Launch, installer and uninstaller values
  are chosen from searchable, keyboard-navigable lists (path + size, Refresh,
  Browse folder, manual entry kept as an advanced fallback); games without a
  local install keep the manual fields. `check_game_executable` validates every
  saved value (traversal, absolute and symlink escapes rejected) and syncs the
  local installed row; the listing is invalidated after move, repair, installer
  run and install completion.
- GameVault folder adoption rework (#134): matched folders are never silently
  dropped — a game without a detected executable stays in the list with a note,
  ranked `.exe` candidates and path-bearing warnings, and can be linked with a
  manually chosen executable. Discovery walks 4–8 levels (default 6), follows
  junctions/symlinks with loop guards, retries long Windows paths, skips
  redist/support/installer folders and never auto-picks among unrelated
  executables. Multiple GameVault roots are stored, scanned together, deduped
  by canonical folder, with add/remove/reorder and read-only auto-detection;
  per-root failures are reported instead of a generic "no executable".
- Big Picture refreshes on open and plays a short entrance (#142): one throttled
  refetch of games/installed/updates with cached content kept on failure, a
  subtle 434 ms staged opacity/transform reveal (backdrop, hero, header, cards
  with 22 ms stagger) using the house easing, no replay on shelf/index changes,
  and an opacity-only 120 ms branch under `prefers-reduced-motion`.
## [0.3.0] - 2026-11-11

### Added

- PostgreSQL backend option (#46): `LUDEX_DATABASE_URL=postgres://…` (or
  `LUDEX_DATABASE_BACKEND`) runs the server on PostgreSQL while SQLite stays the
  default. A mirrored migration set (`migrations_postgres/`, 0001–0019), a
  backend-neutral query layer with `?` → `$n` rewriting and documented dialect
  branches (JSON arrays, case-insensitive indexes, `SUM` casts), a configurable
  pool (`LUDEX_DATABASE_MAX_CONNECTIONS`), redacted connection URLs, backend and
  pool details in `/api/health/details`, a real-PostgreSQL integration test
  (`LUDEX_TEST_POSTGRES_URL`, skipped by default), and `docs/POSTGRES.md`.
  `ludex-backup` now refuses PostgreSQL explicitly (use `pg_dump`/`pg_restore`).

  and local launcher entries are merged by a pure model, matched imports show a

## [0.2.0] - 2026-11-10

### Added

- Global downloads manager: queue and history, background installs that survive
  closing the install window, per-job progress/speed/ETA, cancel and resume.

  login fallback.

  isolated per account, 2 GiB default limit. Ludusavi automation is roadmap.

  are requested and cached locally.
- Playwright browser E2E suite (library, search/filter, detail, download, setup,
  ingest, navigation, Big Picture). The `E2E` job is a required check and the
  release workflow is gated on it.

  SHA-256 for pull-based GitOps updates.
