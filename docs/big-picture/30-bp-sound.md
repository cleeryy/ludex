## Goal

Give Big Picture an audible identity: short, dry, original cues for movement, confirmation, refusal, launch and completion, plus a haptics layer with a strength setting. A player three metres from the screen should know what happened without looking at the hint strip — and should never hear a Nintendo or Sony sound, a chiptune cover, or anything at all while a game is running.

The haptics layer already does the hard part: it is throttled to one pulse per 120 ms (`gamepad.ts:208`), refuses pads without a `vibrationActuator`, and never throws. Sound extends that, it does not replace it.

## Sound language

**“Dry archive.”** Every cue is a short transient plus one pitched body; paper, wood and a struck glass, never a square wave. Rules:

- mono, 48 kHz, 16-bit; no reverb longer than 200 ms; no more than three partials at once; no melody longer than four notes.
- 45–700 ms; loudness target −20 dBFS RMS for movement, −12 dBFS peak for confirmation; no cue over −10 dBFS.
- No sound is played twice in a row for the same event; move is deduplicated at 24 ms.
- Originality is a hard requirement: the cues are synthesised from parameters in a committed script, not sampled from a console, a game, or a sample pack. No motif is copied from any platform's startup, home menu or notification sound.

### Cue table

| Cue | Fires on | Length | Construction | Peak |
| --- | --- | --- | --- | --- |
| `move` | focus moves one card/row | 45 ms | 2 ms noise tick + 1.5 kHz sine body, 20 ms decay | −20 dBFS |
| `confirm` | A on an action | 90 ms | 660 Hz + 990 Hz (fifth), 70 ms decay | −12 |
| `back` | B one level | 100 ms | 880 Hz → 587 Hz, 80 ms | −14 |
| `openGroup` | an app or panel opens | 140 ms | 196 Hz knock + 700 Hz air | −16 |
| `closeGroup` | an app or panel closes | 120 ms | 165 Hz knock, softer | −18 |
| `tabChange` | LB/RB shelf or category | 70 ms | 900 Hz band-passed air | −20 |
| `error` | a refused action | 220 ms | 220 Hz + 233 Hz (minor second), fast decay | −12 |
| `launch` | a game starts | 350 ms | 330 → 440 → 660 Hz rise, tail to silence | −10 |
| `achievement` | an unlock | 700 ms | 523 + 784 + 1046 Hz bell arpeggio, 60 ms apart | −14 |
| `installComplete` | a job reaches `done` | 400 ms | 660 + 880 Hz settle | −14 |
| `power` | quit/restart confirmed | 500 ms | 440 → 220 Hz, noise tail | −12 |
| `overlayOpen` | quick menu, search, layout picker | 120 ms | air sweep 400 → 900 Hz | −20 |
| `overlayClose` | same, closing | 100 ms | 900 → 400 Hz | −22 |
| `notification` | a toast or unread arrives | 300 ms | 880 Hz bell + soft tail | −16 |

Borrowed cue points (move / confirm / back / tab) are deliberately conventional so the controller feels immediate; everything else is Ludex's own vocabulary. `error` is a minor second, not a buzzer: this interface never shouts.

## Technical design

### Format and pipeline

- **WAV, mono, 48 kHz, 16-bit** in `apps/web/public/sounds/bp/bp-<cue>.wav`. Total budget ≈ 310 KB for all fourteen cues (a 45 ms cue is 4.3 KB), served by the same static pipeline as the icons, no hashing needed.
- WAV over OGG/AAC because it needs no codec support matrix, decodes sample-accurately for latency, and stays inside the bundle budget at this length. If the budget ever exceeds 512 KB, transcode to OGG Vorbis and keep WAV as the fallback; do not do it before it is needed.
- Sources are generated by `scripts/bp-sounds.mjs` (Node, no runtime dependency): it writes the PCM, applies the envelopes from the table above, and prints the manifest rows. The generated files and the script are committed together, so provenance is reproducible.
- `apps/web/public/sounds/bp/LICENSE` states CC0-1.0, “generated by scripts/bp-sounds.mjs for Ludex; contains no third-party samples”. This is the licensing answer for every future contributor.
- CI test: every `CueId` has a manifest entry, every file exists, total size < 512 KB, no file longer than 1 s.

### Manager

`apps/web/src/lib/ui-sound.ts`, a module singleton with a narrow, testable surface:

```ts
export interface CueSpec { file: string; gainDb: number; maxVoices: number; essential: boolean }
export interface SoundManager {
  play(cue: CueId): void;
  preload(): Promise<void>;
  setPrefs(next: SoundPrefs): void;
  stopAll(): void;
}
export function createSoundManager(backend: SoundBackend, prefs: () => SoundPrefs): SoundManager
export const uiSound: SoundManager   // singleton used by the screen; tests build their own
```

- `AudioContext({ latencyHint: "interactive" })` created once; `fetch` + `decodeAudioData` for all cues in parallel at mount, with the context suspended; `resume()` on the first `pointerdown`/`keydown`/gamepad action. If creation before a gesture throws (older WebKit), fall back to creating it inside that first handler and re-run `preload()`.
- Graph: `source → per-cue gain → master gain → DynamicsCompressor → destination`. The compressor is a safety limiter, not a sound; it prevents clipping when `installComplete` and `notification` overlap.
- Schedule at `ctx.currentTime + 0.004`, never `0`. Measure input → `start()` in development (`?gamepadDebug=1` already exists, `lib/gamepad.ts:96-105`) and keep it under 25 ms including the rAF poll.
- Polyphony: 3 voices per cue, 8 total, oldest dropped. Never queue a stale cue; a console that lags behind the input is worse than a silent one.
- `move` dedupe: 24 ms. `hapticPattern` already throttles at 120 ms; leave that alone.
- Guards, in order: `enabled`, `volume > 0`, `document.visibilityState === "visible"`, `!gameRunning`, cue not in cooldown. Any failed guard is a silent no-op, never a throw.

### Preferences

Extend the existing device-local record (`controller.ts:310-362`) rather than adding a second storage key:

```ts
interface BigPictureControllerPrefs {
  profileId: string | null;
  haptics: boolean;
  hapticsStrength: "off" | "standard" | "strong";   // new, default "standard"
  sound: { enabled: boolean; volume: number };       // new, default { enabled: true, volume: 0.45 }
}
```

`sanitizeControllerPrefs` gains defaults for missing/garbage fields, so existing stored JSON keeps working with no migration. The key stays `ludex.bigPicture.controller`, scoped per server by `scopedStorageKey` (`big-picture.tsx:87-94`).

Volume is stored as 0–1 and applied as `gain = volume²`, so 45 % sits near half loudness instead of half amplitude.

Defaults, and why:

- **Sound on, 45 %.** The point of the issue is console feel, and 45 % is audible without becoming an event. It cannot surprise anyone: the context only resumes on a gesture, so the first cue is the first press.
- **Haptics on, `standard`.** Already shipped that way (`controller.ts:319-322`); changing it would feel like a regression. Add strength instead of a second toggle. `off` remains available in both places.
- Both are per device, not per account: a TV and a handheld want different volumes, exactly like the layout (`layout.ts:19-24`).

### Event mapping

`apps/web/src/components/big-picture/cues.ts` is pure and owns the whole decision:

```ts
export type CueId = "move" | "confirm" | … ;
export function cueForCommand(
  command: BigPictureCommand,
  view: { moved: boolean; overlayOpen: boolean; appOpen: boolean; launched: boolean },
): CueId | null;
```

| Command | Cue | Notes |
| --- | --- | --- |
| `move` | `move` when `moved`, else `null` | an edge press is silent: there was no movement to confirm |
| `shelf`, `page` | `tabChange` | |
| `highlight` | `move` | overlays |
| `activate` | `confirm` | then `launch` if a game actually starts |
| `select` | `confirm` | |
| `close` | `overlayClose` when an overlay closes, `back` when a level pops | |
| `open` | `overlayOpen` | |
| app enter / exit | `openGroup` / `closeGroup` | system apps from `28-bp-console.md`, not overlays |
| `layout` | `overlayOpen` | |
| `game`, `none` | `null` | the game page leaves Big Picture |
| `exit` | `null` | the confirm overlay already played `overlayOpen`; `power` plays on the confirmed action |

Wiring is one place: `runCommand` (`big-picture.tsx:595-637`) calls `play(cueForCommand(command, view))` after execution, so keyboard and pad produce identical audio. A second set of hooks covers events that are not commands:

| Event | Hook |
| --- | --- |
| Refused action | `refuse(reason)` helper: `error` cue + toast; replaces the silent return at `big-picture.tsx:433` |
| Launch | `confirm()`’s launch branch: `launch` on press, `error` if the mutation fails |
| Install complete | `useDownloads` phase transition to `done` in a tiny `useCueOnInstallDone()` ref |
| Achievement | P3: diff `api.meAchievements()` `unlockedAt`; no cue until the achievements app exists |
| Notification | toast push from the notifications poller, once per new unread |

### Haptics

Reuse `hapticPattern` (`gamepad-core.ts:417-436`) and `vibrate` (`gamepad.ts:206-219`); add one pattern for `error` (two 40 ms pulses, 60 ms apart) and scale magnitudes by `hapticsStrength` (`standard` ×1, `strong` ×1.35, clamped to 1). Gate stays `prefs.haptics && profile.vibration` (`big-picture.tsx:246`). No haptics on cues the pad did not cause: keyboard and mouse never rumble.

### Reduced motion

`prefers-reduced-motion` is a vestibular setting, not an audio one, but five of these cues exist only to decorate movement and transitions. Under reduced motion, mark them `essential: false` and suppress them: `overlayOpen`, `overlayClose`, `openGroup`, `closeGroup`, `tabChange`. Keep `move`, `confirm`, `back`, `error`, `launch`, `power`, `installComplete`, `notification`, `achievement`. This is a product decision, documented in the module header; the functional feedback never disappears.

### Gameplay rule

No Big Picture cue may play while a game is running, even if the window is still visible or focused behind a borderless game.

- `launch.mutate` sets `gameRunning = true`, calls `stopAll()`, and mutes the manager; `native.onGameExited` clears it (`lib/native.ts:765`).
- `onGameExited` is currently wired only by `useNativeEvents`, mounted in `AppShell` (`app-shell.tsx:270`), which Big Picture is outside of. Move that hook to `app.tsx` inside the router (also required by `28-bp-console.md`), or mount the lifecycle hook in Big Picture too.
- The in-game overlay is a separate entry (`app.tsx:245-246`, `components/overlay/overlay-window.tsx:33`). It may play `overlayOpen`, `overlayClose`, `confirm`, `back` and `error` only, only while the overlay is open. The game window never loads the app, so there is no path for a cue to leak into gameplay.

### Settings UI

Two surfaces, one store:

1. Big Picture → Settings → Sound (from `28-bp-console.md`):
   - `UI sounds` toggle
   - `Volume` slider, 0–100 in 5 % steps, `aria-valuetext="45 percent"`, Left/Right on the focused row (the pattern in `overlay-panel.tsx:169-181` is the pointer version)
   - `Test` actions for `move`, `confirm`, `error`
   - `Haptics` toggle, `Strength` choice (Off / Standard / Strong), `Test pulse`
2. Desktop Settings → Appearance, next to `BigPictureLayoutPanel` (`appearance-panel.tsx:601`): a compact `BigPictureSoundPanel` with the same two controls and a line linking to the console settings. Same store, so a change applies live in a running Big Picture, exactly like the layout panel (`layout-panel.tsx:16-32`).

All copy through `t()`; run `pnpm --filter @ludex/web i18n:write`.

## Scope

### P1 — the manager and the essential six (1 PR)

- `lib/ui-sound.ts` + `lib/ui-sound.test.ts` with a fake backend: mute, volume clamp, polyphony drop, visibility guard, cooldown.
- `public/sounds/bp/` six cues: `move`, `confirm`, `back`, `error`, `launch`, `power`; `LICENSE`; `scripts/bp-sounds.mjs`; asset/size test.
- `cues.ts` + `cues.test.ts`: the full command table, including `null` cases. An id whose asset ships in P2 is a no-op until then.
- `runCommand`, `refuse()` and `confirm()` wiring. `refuse()` is introduced by `28-bp-console.md`; create it here if the shell has not landed.
- Prefs extension + sanitize test; desktop `BigPictureSoundPanel` (UI sounds, volume). The console Sound section is added with the settings app in `28-bp-console.md` P2.
- Defaults on at 45 %, gesture-gated.

### P2 — the rest of the vocabulary (1 PR)

- Seven remaining cues: `tabChange`, `openGroup`, `closeGroup`, `overlayOpen`, `overlayClose`, `installComplete`, `notification`.
- Reduced-motion suppression table + test.
- Haptics strength + `error` pattern + test pulse.
- `gameRunning` mute + move `useNativeEvents` (shared with `28-bp-console.md`).
- TV toast cue on the BP surface only.

### P3 — social and in-game overlay (1 PR)

- `achievement` cue driven by an `unlockedAt` diff.
- In-game overlay cues (`overlayOpen`, `overlayClose`, `confirm`, `back`, `error`), gated by the overlay being open.
- A dev-only latency line in the gamepad debug panel: input timestamp → `AudioContext` start.

## Acceptance

- [ ] Every command that changes focus or acts produces its cue in the same frame; keyboard and pad are indistinguishable.
- [ ] A press at the edge of a row is silent; a refused action plays `error` **and** shows a reason.
- [ ] Muting in either settings surface silences a running Big Picture immediately; volume is clamped to 0–1 and persists per device.
- [ ] No cue plays while a game is running, except the in-game overlay's own open, close and error cues; the first Big Picture cue after exit plays on the next input.
- [ ] Reduced motion suppresses the five decorative cues and keeps the functional ones.
- [ ] No copyrighted or sampled audio: every file is generated by the committed script; `LICENSE` present; total < 512 KB.
- [ ] Haptics strength changes the felt intensity; `Off` and the profile's `vibration: false` both silence it.
- [ ] Tests cover the event map, mute, volume, polyphony, reduced motion, prefs sanitize, asset manifest.
- [ ] `pnpm --filter @ludex/web check`, `test`, `build`; i18n gate; no dependency added.

## Out of scope

- Music, ambience, voice packs, spatial audio, per-game soundtracks.
- Any sound inside a running game; the in-game overlay is the only exception and only while open.
- Audio ducking of other applications; Ludex does not own the system mixer.
- User-imported sound packs; the cue set is fixed and original.
- Haptics on keyboard or mouse input.
- Changing the existing 120 ms haptic throttle (`gamepad.ts:208`) or the profile `vibration` semantics.

## Risks

| Risk | Mitigation |
| --- | --- |
| Autoplay policy blocks the context | create suspended at mount, `resume()` on the first gesture, re-`preload()` if creation is deferred |
| First cue late because decode has not finished | preload at mount; if a cue is not decoded, play nothing rather than a late sound |
| 14 WAVs inflate the bundle | 310 KB budget enforced by test; OGG transcode only if the budget is raised |
| Cue fatigue in a long session | 45 % default, `move` dedupe, no cue on edge, no loop, volume one row away |
| Achievement cue with no data source | ship the cue in P3 with the achievements app; no fake trigger |
