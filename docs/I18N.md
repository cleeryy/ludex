# Internationalisation and themes

Ludex ships English and French as official locales and the top-10 target set
from #139 (Simplified Chinese, Russian, Spanish, Portuguese (Brazil), German,
Japanese, Korean, Polish, Turkish) as preview catalogs, plus a few extended
locales. The web client also has light, dark and system themes, an installable
PWA shell and an offline fallback. This document is the contribution guide for
both.

## How the web client translates

English is the source language, so **the English message is the message id**
(the same model as gettext `msgid`). Source code calls `t("…")` with the exact
English copy; locale JSON files map that id to a translation. Missing entries
fall back to the English id, which means a partially translated locale is
always usable and never shows a raw key.

The runtime lives in [`apps/web/src/lib/i18n.tsx`](../apps/web/src/lib/i18n.tsx).
`apps/web/scripts/i18n.mjs` owns the catalog: it extracts every message id from
`t()`, `tn()` and `tr()` calls, writes `en.json`, checks key parity, duplicate
ids, placeholders, plural categories, RTL coherence, coverage thresholds and the
pseudo-locale, and keeps `coverage.json` up to date.

```
apps/web/src/locales/
  manifest.json    locale registry: code, native name, direction, status, tier, file, Intl tag
  en.json          generated identity catalog (one key per UI string)
  fr.json          official translation, must stay at 100 %
  de.json          preview, must reach 100 % to be promoted
  …                one flat JSON map per locale, keyed by the English id
  coverage.json    generated per-locale coverage, shown in Settings
```

### The three helpers

```tsx
import { t, tn, tr } from "@/lib/i18n";

t("Library");
t("Last played {when}", { when: formatRelative(game.lastPlayedAt) });
tn(count, "1 game", "{count} games");
tr("{who} added {game} to the library", { who, game: gameLink });
```

- `t(id, vars?)` interpolates `{name}` placeholders. Numbers are formatted with
  `Intl.NumberFormat` for the active locale.
- `tn(count, one, other, vars?)` chooses the plural form with
  `Intl.PluralRules`. Translators add `|category` entries keyed on the plural
  message id, e.g. `"{count} games|one": "{count} jeu"` or the Russian/Arabic
  `|zero`, `|two`, `|few`, `|many`, `|other` variants. The checker rejects a
  category the locale does not have and a plural set without `|other`.
- `tr(id, vars)` is the rich-text variant: values may be React nodes, so a
  sentence can keep its inline links and code spans while translators reorder
  the sentence.

Placeholders must match between English and every translation; the checker
enforces this. Do not translate message ids, code spans, product names, file
names or environment variable names.

Dates, numbers, relative times, lists and plural categories always go through
`Intl.DateTimeFormat`, `Intl.NumberFormat`, `Intl.RelativeTimeFormat`,
`Intl.ListFormat` and `Intl.PluralRules`. Never hand-format a date and never
build a byte size or a number by concatenation.

### Changing copy or adding a string

1. Wrap the copy in `t("…")` (or `tn`/`tr`) in the component. For JSX text, the
   expression form is `{t("…")}`; for attributes use `label={t("…")}`.
2. Run `pnpm --filter @ludex/web i18n:write`. This regenerates `en.json` and
   `coverage.json` and prints the per-locale coverage table.
3. Translate the new French string in `fr.json` (the checker fails if it is
   missing; French is official). Preview locales may lag and fall back to
   English.
4. Run `pnpm --filter @ludex/web i18n:check` (also part of `check` and `build`).

Never edit `en.json` or `coverage.json` by hand: both are generated.

## The locale registry

`src/locales/manifest.json` is the single source of truth. The picker, the
runtime, the coverage gate and the CI checks all read it; there is no TypeScript
list to update.

```json
{
  "code": "pt-BR",
  "label": "Português (Brasil)",
  "englishLabel": "Portuguese (Brazil)",
  "dir": "ltr",
  "status": "preview",
  "tier": "top10",
  "reviewed": false,
  "file": "pt-BR.json",
  "intl": "pt-BR"
}
```

| Field | Meaning |
| --- | --- |
| `code` | BCP-47 tag (`pt-BR`, `zh-CN`, `ar`). Used for `<html lang>`, the storage key and the `?lang=` override. |
| `label` | Native name, shown first in the picker. Never localise it. |
| `englishLabel` | English name, shown under the native name and used in reviews. |
| `dir` | `ltr` or `rtl`. Must agree with the RTL script list: `ar`, `he`, `fa`, `ur` are RTL, everything else is LTR. |
| `status` | `official` (reviewed, complete, enforced at 100 %), `preview` (shipped, selectable from 95 %), `pseudo` (`en-XA`, never shipped as a file). |
| `tier` | `source` (`en`), `top10` (#139 target set, must reach 100 %), `extended` (everything after), `dev` (pseudo-locale). |
| `reviewed` | Whether a native speaker reviewed the catalog. Drives the badge copy. |
| `file` | Expected catalog file relative to `src/locales`; `null` only for the pseudo-locale. |
| `intl` | Intl locale for dates, numbers, plurals. May differ from `code` (`en-GB` for `en`). |

Current registry:

| Code | Native name | Dir | Status | Tier | Coverage |
| --- | --- | --- | --- | --- | --- |
| `en` | English | ltr | official | source | 100 % |
| `fr` | Français | ltr | official | top10 | 100 % |

## Coverage gate and language selection

- **95 % is the floor for the picker** (`SELECTABLE_PERCENT` in
  `src/lib/i18n.tsx`). A locale below it is not listed: the UI would mix two
  languages on the same screen. The file may stay in the repository — the gate
  hides it, the CI reports it, and `?lang=xx` still opens it for reviewers.
- **Official locales are always complete.** The checker fails when `en` or `fr`
  loses a translation, so an official locale can never fall back mid-screen.
- **Top-10 locales must reach 100 %.** A shipped `top10` file below 100 % warns,
  and one below the floor is hidden just like any other preview (the warning
  says which). `--strict` turns both warnings into errors: that is the release
  gate, so a half-finished top-10 catalog can never become official by accident.
  Promotion happens after a native review, in the PR that sets `status` and
  `reviewed`.
- **Fallback is key by key.** A missing entry renders the English copy, never the
  key and never an empty string. A locale at 96 % shows four English strings,
  not a half-translated screen.
- **The choice is per device.** It is stored in `localStorage["ludex.locale"]`,
  applied before the first paint by the inline script in `index.html`, and
  changed at runtime without a reload (`setLocale` loads the catalog and
  remounts the tree).
- **First run follows the browser.** `navigator.languages` is matched against the
  registry — exact tag first (`pt-BR`), then the best-covered sibling of the base
  language (`pt` → `pt-BR`, `zh` → `zh-CN`) — and only among locales that clear
  the gate. The match is stored once, so later visits keep it.
- **`?lang=xx` overrides for the session** (query string or hash query, e.g.
  `#/settings?lang=de`). It is not persisted and it ignores the coverage gate, so
  a reviewer can open a 12 % catalog on purpose.

## Validation and CI

`node scripts/i18n.mjs` is the gate. It fails when:

- source copy is not in `en.json` (forgot `i18n:write`) or `en.json` has stale
  ids, duplicate ids, or is not sorted;
- an official locale is missing a translation;
- any locale has an empty value, an unknown id, a duplicated id, a
  `{placeholder}` mismatch, a plural category the locale does not have, or a
  plural set without `|other`;
- `coverage.json` is stale;
- the registry is incoherent: unknown status/tier, duplicate code, wrong
  direction for an RTL base language, a file name that does not match the code,
  an Intl tag the runtime does not know, a missing top-10 entry, or an
  `index.html` RTL list that disagrees with the manifest;
- the pseudo-locale cannot be generated for a message (lost bracket, lost
  placeholder, no expansion).

A preview locale (including a top-10 one) can slip below its target while the
source grows: it is hidden from the picker, the gate prints a warning, and the
build stays green. `--strict` instead fails when a shipped top-10 file is below
100 %; it runs in CI as an advisory step until the translation lanes land, then
becomes blocking. The hardcoded-English scan is always advisory (`--hardcoded`
prints it); a false positive must not block a release.

Commands (`apps/web`):

| Command | What it does |
| --- | --- |
| `pnpm i18n:check` | the gate (same check as `build`) |
| `pnpm i18n:strict` | gate + 100 % for shipped top-10 files |
| `pnpm i18n:write` | regenerate `en.json` + `coverage.json` |
| `pnpm i18n:coverage` | refresh `coverage.json` only (after a locale file lands) |
| `pnpm i18n:hardcoded` | list hardcoded English strings (advisory) |
| `pnpm i18n:pseudo` | write the `en-XA` catalog to the temp dir for inspection |

## Adding a locale without touching TypeScript

A translator adds a language with two JSON files and no code:

1. Copy `en.json` to `src/locales/xx.json` and translate the values. Start with
   navigation, settings, library, downloads and the empty states; everything
   else falls back to English while the file is under the gate.
2. Add an entry to `src/locales/manifest.json` (see the field table above). For
   a right-to-left language set `"dir": "rtl"`; for a top-10 language set
   `"tier": "top10"`.
3. Run `pnpm --filter @ludex/web i18n:coverage` to refresh coverage, then
   `pnpm --filter @ludex/web i18n:check`.

The locale appears in Settings as soon as it clears 95 %, and the chunk is
lazy-loaded by Vite through `import.meta.glob`, so the new file is discovered at
build time. Set `"reviewed": true` and `"status": "official"` only after a
native review; from then on CI requires 100 %.

Arabic (`ar`) is deliberately `preview` and unreviewed: it was machine-seeded to
prove the RTL path and stays hidden until it reaches the gate. Open it with
`?lang=ar`.

## Glossary

Keep these seven terms consistent across locales; they carry product meaning.

| English | Meaning in Ludex | Notes |
| --- | --- | --- |
| Library | The whole collection of games the server knows about. `fr`: **bibliothèque**. | Never "catalogue", never "collection" (that is a user shelf). |
| Install | Copying game files to this device so they can be launched. `fr`: **installation** / **installer**. | Distinct from *download* (fetching an archive) and *import* (adopting files already on disk). |
| Snapshot | A point-in-time copy of a save file kept by the server. `fr`: **instantané**. | Never "backup" in UI copy: backups are the desktop feature, snapshots are per-save versions. |
| Playtime | Accumulated time spent in a game, shown per game and per account. `fr`: **temps de jeu**. | Use the locale's natural duration wording, not "heures de jeu". |
| Save | The game's progress files (Ludusavi-compatible). `fr`: **sauvegarde** (the files), **enregistrer** (the verb "save settings"). | Two different words in most languages; keep the UI verbs separate from the file noun. |
| Match | A library entry linked to a metadata provider's record. `fr`: **correspondance**. | "Match" is a noun here, not a game or a sports term. |
| Controller | A gamepad. `fr`: **manette**, `de`: **Controller**, `es`: **mando**. | Not "joystick" and not the person who manages something. |

Additional rules:

- Product names (`Ludex`, `Steam`, `GOG`, `IGDB`, `Ludusavi`, `Sunshine`) stay
  as-is.
- UI nouns stay short enough for a 44 px control and a 390 px screen; test the
  picker and the settings rows before opening the PR.
- Keep the imperative mood used by English buttons ("Save changes", "Try
  again"), the same sentence case, and the same terminal punctuation.
- Accessibility labels (`aria-label`) are copy too; they must be translated.

## Translation workflow

1. **Draft.** Copy `en.json`, run `pnpm i18n:coverage` regularly to see where
   you are. AI-assisted drafts are welcome but never merged unreviewed.
2. **Review.** A native speaker reads the diff (`git diff -- src/locales/xx.json`)
   or the app with `?lang=xx`, checks length, plurals and punctuation, then sets
   `"reviewed": true` in the manifest.
3. **Community PR.** One PR per locale, the JSON file plus the manifest entry.
   CI runs the same gate as `main`, so a partial file is fine as long as it is
   under the gate and does not break the registry.
4. **Weblate / Crowdin.** Both work on the same flat JSON: point the tool at
   `apps/web/src/locales/en.json` as the source and `xx.json` as the
   translation, keep "key = source string" disabled (the key is the id), and
   preserve `{placeholders}`. A nightly job can `pnpm i18n:coverage` after the
   tool pushes. Do not let a bot regenerate `en.json`.
5. **Promotion.** When the catalog is at 100 % and reviewed, flip `status` to
   `official` and `reviewed` to `true`. CI then enforces completeness forever.

## Pseudo-locale (en-XA)

`en-XA` is a generated locale: every English string is wrapped in `⟦…⟧` and
mapped to accented letters, and `{placeholders}` are left untouched. It ships no
file and never appears in the picker.

```bash
# open the app with a pseudo catalog
pnpm --filter @ludex/web dev
# then visit http://localhost:5173/?lang=en-XA

# inspect the generated catalog without a browser
pnpm --filter @ludex/web i18n:pseudo
```

Use it to find:

- **Hardcoded strings.** Text that stays plain ASCII never went through `t()`.
- **Truncation.** The pseudo text is slightly longer; a missing `⟧` means the
  container clips. German, Russian and Japanese hit this hardest.
- **Placeholder bugs.** If `{count}` is missing from the pseudo text, the
  translation or the interpolation is wrong.

`pnpm i18n:hardcoded` complements it with a static scan of JSX text and the
`aria-label` / `placeholder` / `title` / `alt` attributes. It is advisory: the
remaining hits are real bugs in unmigrated screens, tracked separately.

## RTL rules

- The document direction is set before the first paint from the stored locale
  (`index.html` inline script, `LUDEX_RTL_LOCALES`) and kept in sync by
  `I18nProvider`. The script's list and the manifest must agree; the checker
  fails otherwise.
- New layout code uses logical properties: `ps-*`/`pe-*`, `ms-*`/`me-*`,
  `start-*`/`end-*`, `text-start`/`text-end`, `border-s`/`border-e`.
- Older screens still contain physical helpers (`ml-auto`, `pl-3`, `left-2`,
  `border-l-2`). `styles/index.css` contains a deliberately small `[dir="rtl"]`
  bridge for those classes. New code must not add physical helpers.
- Directional icons (back/next arrows, chevrons) carry `rtl:-scale-x-100`.
- Arabic falls back to the system Arabic font because the Latin display faces
  have no Arabic glyphs. Chinese, Japanese and Korean use the platform CJK
  fallbacks; do not force a Latin font on them.

Manual RTL smoke: `pnpm --filter @ludex/web dev`, open `/?lang=ar`, and check at
390 px that `document.documentElement.dir === "rtl"`, the page has no horizontal
overflow, the mobile tab bar is reachable, and every arrow points the right way.
Arabic is under the gate, so the picker hides it — `?lang=ar` is the supported
way in.

## Themes

Themes are client preferences exposed in Settings → Appearance (#140). The
registry is `src/theme/themes.json`: five complete palettes (`midnight`,
`light`/Paper, `nord`, `gruvbox`, `amber`), each with the same semantic token
set. `scripts/theme.mjs` generates the static fallback stylesheet; components
only use Tailwind utilities backed by those custom properties. `system` follows
`prefers-color-scheme` and reacts to OS changes.

Accents and background tints are derived at save time and validated against
the current base. Imported themes are checked for unknown/missing tokens, hex
format and WCAG contrast before they can become active. The resolved variable
map is stored in `localStorage["ludex.theme"]` and replayed by the inline boot
script before the first paint.

`src/styles/tokens.test.ts` enforces token completeness and WCAG AA (4.5:1
text, 3:1 focus) for every built-in theme; `src/styles/no-hardcoded-colors.test.ts`
fails when a component or stylesheet contains a literal colour. Add new pairs
to `CONTRAST_PAIRS` in `src/theme/registry.ts` when introducing a new
foreground/background combination.

## PWA and offline

- `public/manifest.webmanifest` declares the name, standalone display, theme
  colours, maskable 192/512 icons and shortcuts.
- `public/sw.js` is versioned by a content hash injected at build time
  (`vite.config.ts`). It precaches the shell (HTML, CSS, JS, fonts, icons,
  manifest and `offline.html`) and deletes old `ludex-*` caches on activate.
- Navigation is network-first with the cached shell as fallback. Static assets
  are cache-first. Only the public `/api/media/` image cache is cached; every
  other `/api/` request (including auth and JSON) goes straight to the network.
- A waiting worker never activates on its own: the shell shows **Reload now**
  and posts `SKIP_WAITING` on click.
- Install prompt is deferred, dismissible for 30 days
  (`localStorage["ludex.pwa.installDismissedAt"]`).
- All locale JSON chunks are precached, so switching language offline works
  after the first visit.
- `public/offline.html` is the last-resort page when the shell cache is empty.

The service worker is registered only in production builds
(`import.meta.env.PROD`); `vite dev` never serves a stale shell. To smoke it:

```bash
pnpm --filter @ludex/web build
pnpm --filter @ludex/web preview --host 127.0.0.1 --port 4174
# open http://127.0.0.1:4174, wait for the worker, then reload with DevTools
# Network set to Offline; the shell (or offline.html) must render.
```
